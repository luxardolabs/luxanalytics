## Schema / Migrations

- **007_client_event_id — additive:** a nullable `events.client_event_id` and a unique index on `(app_id, client_event_id)` WHERE NOT NULL. It runs at startup like every migration; building the index takes a write lock on `events` for the time it takes on prod's row count. LUXANALYTI-68.

- **005_drop_timestamp_indexes — DESTRUCTIVE (index drop only, no data):** drops `ix_events_app_{name,user,session}_timestamp`, superseded by the `*_received` indexes since 002. Applied automatically at startup (`alembic upgrade head` in the lifespan). Downgrade recreates them. LUXANALYTI-51.

## Fixes

- An app could not be deactivated from its edit panel: an unchecked Active toggle sends no field, and the router wrote `is_active = NULL` (500, NotNullViolation). Unchecked now means inactive. LUXANALYTI-63.
- Creating an app with a taken App ID showed nothing: the 400 carried no swap header, so htmx dropped it. The message now appears in the form's error box.
- `GET /api/v1/stats/overview` was unauthenticated: cross-app event totals, unique-user counts and top event names, readable by anyone. It now requires the dashboard session and returns a typed contract. LUXANALYTI-62.
- `POST /set-app-context` was unauthenticated: anyone could set the dashboard's app-context cookie. It now requires the dashboard session, like every dashboard route. LUXANALYTI-58.
- **SDK-facing:** ingest answered every bad request with 500: a malformed event (e.g. no `name`) or a payload that is neither an object, `{"events": [...]}`, nor a list. Now 422 / 400, so an SDK drops bad data instead of retrying it forever; only a real server failure is a 500. LUXANALYTI-61.
- DSN auth turned every server error during the app lookup into a 401, so a database outage looked like bad credentials to the SDK. Only a malformed header is a 401 now.
- `POST /login` had no rate limit: unlimited password guessing. Now slowapi, 5/minute per real client, 429 + Retry-After (FLEET-RATE-LIMIT-STANDARD). LUXANALYTI-58.
- Every client shared ONE rate-limit bucket: behind nginx `request.client` is the proxy for everyone. The IP limits now key on the real client via a trusted-proxy-aware X-Forwarded-For read (`app/core/client_ip.py`). LUXANALYTI-58.
- The rate-limit middleware re-ran a request whose handler raised, and swallowed the error; a rate-limited (in-memory fallback) or undecodable-deflate request got a 500 instead of 429/400. LUXANALYTI-59.
- OpenTelemetry setup could silently switch tracing off (`add_span_processor` on the API provider, swallowed).
- Every HTML page returned 500 after the Starlette 1.x bump (`0cb252e`, never deployed): `TemplateResponse` moved to the `(request, name, context)` form across the wrapper and all 37 call sites; `tests/test_pages_render.py` now renders `/login` and an authenticated dashboard page. LUXANALYTI-9.
- Open redirect after login (`next` accepted absolute and `//host` URLs). LUXANALYTI-1.
- CORS reflected any origin with credentials; TrustedHost accepted any Host in prod; middleware order was inverted; session cookie `Secure` was a DEBUG dial. LUXANALYTI-1.
- Release image tag was derived from the checkout directory (`luxardolabs.luxanalytics`). LUXANALYTI-53.

## Notes

- AGPL-3.0-only licence added (LUXANALYTI-42).
- The "All" time range: the overview and journey pages divided by `hours=0` (500); with "All apps" every query built an empty `and_()` (removed in SQLAlchemy); the events list and the journey's raw-SQL panels read "the last 0 hours" and showed nothing. All-time now means all time everywhere.
- User profile: errors and screens came from the user's newest 50 events only, so older errors vanished ("Errors (0)"); both are now queries over the whole history, and the headings read "N of total".
- Key deep-dive: "Occurrences", unique values and the distribution were computed from a 200-event sample; they are SQL aggregates now. JSON null / "" count as no value everywhere, so totals and rows agree.
- A `/` or `?` in an SDK-sent user id, session id or property key made the events and explorer pages 500 or broke the link; values are percent-encoded and the panel routes take `{…:path}`.
- The performance page 500ed when no event of an operation had a `success` flag; a malformed event id was a database error, now 404.
- The apps list ran one stats query per app; now one GROUP BY.
- A failed database or Redis ping left the health span green; it is recorded now.
- Request logging at debug level wrote every header, `Authorization`, `Cookie` and the HMAC signature included; it logs named fields only.
- **SDK-facing (LUXANALYTI-69):** `Content-Encoding: deflate` is zlib (RFC 1950) per RFC 9110, which SDK >= 1.1.0 sends; raw DEFLATE stays accepted for SDK \<= 1.0.2 as legacy-client support. A compressed empty body was a ZeroDivisionError 500 (compression ratio); the fallback's debug log carried the first payload bytes. Both fixed; the log names only the format and sizes.
- **SDK-facing (LUXANALYTI-68):** ingest is idempotent on the event's `id` (the SDK's per-event UUID, resent unchanged on retry). A batch retried after a lost response was stored twice; now a repeated `id` per app, or one repeated within a batch, is acknowledged and skipped. The response adds `duplicates` (additive). Events without `id` are stored as before.
- **Security:** a compressed request was inflated without bound before any authentication; one ~0.5 MB anonymous request grew the worker by ~0.5 GB (and up to ~10 GB under nginx's cap). Inflation now stops at `MAX_REQUEST_SIZE` and answers 413.
- Ingest under concurrency: two requests carrying the same client ids (or devices) in different orders deadlocked on the new unique index (one of each pair got a 500). Rows and device upserts are now written in one key order.
- An `id` that cannot be a key (not a string, empty, over 64 characters, NUL) no longer rejects the batch: before LUXANALYTI-68 an `id` was ignored, so such events are stored without dedupe.
- A NUL in an event's name, user/session id or metadata is a 422, not a database 500; the engine no longer writes statement parameters (event data) into error logs (`hide_parameters`).
- Any custom-validator 422 at ingest (a future timestamp, a blank name) answered 500: the error context held an exception object that is not JSON. Now a 422.
- The bare-list ingest form is capped at 1000 events like `{"events": [...]}` (it had no cap, and above ~2000 events hit asyncpg's parameter limit as a 500).
- `/metrics`: `db_pool_overflow` read -20 at idle (SQLAlchemy counts up from -pool_size); it is now 0..n. `db_pool_size` is described as the configured size.
- **Log consumers:** the in-process startup migrations re-ran the logging setup as `luxanalytics-migrations`, so every later app line carried that service and no environment. The alembic CLI alone sets it now.
- Shutdown closes Redis through `close_redis_client()` (redis-py 8's `aclose`).
- **SDK contract:** the OpenAPI document (`/openapi.json`, DEBUG only) showed no request body for the three ingest routes, so a client contract check passed anything. The body (one event, `{"events": [...]}`, or a list) is now published from the models ingest validates with, with `EventCreate` / `BatchEventRequest` in components.
- **SDK-facing (LUXANALYTI-80):** a timestamp more than `EVENT_TIMESTAMP_FUTURE_TOLERANCE` (60 s) ahead was a 422, and the SDK drops a 4xx batch, so a device with a fast clock lost every event. It is now clamped to the server's receive time. Within the tolerance, and in the past (events queued offline), timestamps are stored as sent.
- **Pre-deploy, prod:** set `COMPOSE_PROFILES=backup` (done in the local `deploy/prod/.env.prod`). It starts `luxanalytics_backup`: a daily gzip `pg_dump` into `backups/` on the node, keeping 14 days (LUXANALYTI-14). The db container restarts with tuning sized to the measured data (shared_buffers 256MB, effective_cache_size 2GB, work_mem 8MB, pg_stat_statements; LUXANALYTI-19).
- **Pre-deploy, verified 2026-10-08:** the prod nginx container's proxy.conf forwards `Host $host` and X-Forwarded-For from private ranges, so the fail-closed TrustedHost is safe. The live site config still exposes /health; `make prod-nginx` replaces it with the repo version.
