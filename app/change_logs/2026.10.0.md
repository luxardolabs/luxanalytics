## Features

- `make test` runs the full suite against a throwaway Postgres under the canonical pytest config; `make db-verify` proves the migration chain builds exactly what the models describe (both in `make check`). LUXANALYTI-17, LUXANALYTI-51.
- Fleet guards onboarded (luxarch / luxlint / luxaudit), `make check`, `make onboard-check`, `make status`, scoped re-run targets. LUXANALYTI-42, LUXANALYTI-47.
- Tracing: `app/core/tracing.py` (`create_service_span`, `record_exception_in_span`); every core and view service method opens a span carrying `app_id` / `event_id` / `user_id` / `session_id`. LUXANALYTI-64; raw user and session ids ride on spans per the observability standard (LUXANALYTI-71).
- `make smoke` probes the deployed dev stack (build commit, static asset, forged Host, entry points); `make dev-deploy` ends with it.
- `make test` runs against a real throwaway Redis as well as Postgres, so the Redis rate-limit path is tested, not only its in-memory fallback.
- Per-event device context: `device_type`, `build_number`, `screen_resolution`, `locale`, `timezone` and `is_testflight` are columns on every event, as they were when it was sent (the `devices` table keeps only each device's latest values). LUXANALYTI-16.
- **SDK-facing (LUXANALYTI-68):** ingest is idempotent on the event's `id` (the SDK's per-event UUID, resent unchanged on retry). A batch retried after a lost response was stored twice; now a repeated `id` per app, or one repeated within a batch, is acknowledged and skipped. The response adds `duplicates` (additive). Events without `id` are stored as before.
- `docs/event-format.md`: the client contract (endpoints, auth, body, idempotency, device context, compression, responses, the keys the dashboard reads). The OpenAPI document publishes the ingest body from the validating models.
- `make seed-sdk-app` (dev/test only): the `sdk-integration` app the Swift SDK's integration tests post to. LUXANALYTI-73.
- Daily database backups on prod (the `backup` compose profile, `scripts/backup.sh`). LUXANALYTI-14.

## Schema / Migrations

Prod is at 004; startup migrates it to 009. See Notes for the backup and rollback steps.

- **009_drop_event_metadata — DESTRUCTIVE only in form (owner-approved):** drops `events.event_metadata`, which after 008 held nothing unique. Rehearsed on a full copy of prod: the upgrade applies, and the downgrade rebuilds the column from the promoted columns plus `properties`, with all 72,624 rebuilt rows containing every original key and value. LUXANALYTI-16.

- **008_event_device_context — additive + backfill:** six nullable `events` columns (`device_type`, `build_number`, `screen_resolution`, `locale`, `timezone`, `is_testflight`) filled from `event_metadata` for every existing row, and written on ingest. Before this, the `devices` table held only each device's latest values, and `event_metadata` was the only per-event copy. Rehearsed on a full copy of prod (72,624 events): it applies cleanly, and 0 rows have a metadata key held nowhere else. LUXANALYTI-16.

- **007_client_event_id — additive:** a nullable `events.client_event_id` and a unique index on `(app_id, client_event_id)` WHERE NOT NULL. It runs at startup like every migration; building the index takes a write lock on `events` for the time it takes on prod's row count. LUXANALYTI-68.

- **006_naming_convention_pks — rename only:** primary keys created before the naming convention (`<table>_pkey`, prod) are renamed to `pk_<table>`; a no-op where the name is already canonical. LUXANALYTI-51.

- **005_drop_timestamp_indexes — DESTRUCTIVE (index drop only, no data):** drops `ix_events_app_{name,user,session}_timestamp`, superseded by the `*_received` indexes since 002. Downgrade recreates them. LUXANALYTI-51.

## Infra / Ops

- **Compose (LUXANALYTI-54):** one `compose.yml` replaces `compose.yml` (dev) + `deploy/prod/compose.yaml`. `deploy/prod/.env.prod` gains `DEPLOY_ENV=prod`, `COMPOSE_PROFILES=backup`, `POSTGRES_VOLUME=luxanalytics-postgres-data`, `REDIS_VOLUME=luxanalytics-redis-data` (the existing volumes; Postgres is now `external`, so a typo cannot create an empty DB). `make prod-sync` ships `compose.yml`, `scripts/init.sql`, `scripts/backup.sh` and `.env.prod`; every prod target runs `-f compose.yml`.
- **Backups (LUXANALYTI-14):** `luxanalytics_backup` runs `scripts/backup.sh`: a daily gzip `pg_dump` into `backups/` on the node, written 0600, keeping the newest 14. Rotation runs only after a dump succeeds and touches only its own `luxanalytics-<stamp>Z.sql.gz` files, so a manual dump survives. The service turns unhealthy when the newest dump is over two days old.
- **Database tuning (LUXANALYTI-19):** shared_buffers 256MB, effective_cache_size 2GB, work_mem 8MB, pg_stat_statements (preloaded, track=top), sized to the measured data.
- **Production settings (LUXANALYTI-22):** startup refuses an unsafe production configuration, and any `ENVIRONMENT` other than `dev`/`development`/`test` counts as production. It needs a `DASHBOARD_PASSWORD` of 12+ characters that is not a default or the username, `DEBUG=false`, and an http(s) `EXTERNAL_URL` with a host.
- `DASHBOARD_PASSWORD` is REQUIRED (non-empty); the `changeme` default is gone.
- **Logging:** the per-container fluentd driver is gone (not a fleet standard). Containers log JSON to stdout (the fleet logging module); the next `up -d` recreates them for that.
- **Image:** builder + runtime stages; no pip/Poetry/gcc in the runtime image; `apt-get upgrade` at build. The release candidate scans 0 fixable HIGH/CRITICAL (was 5). OCI provenance labels; `app` / `test` / `production` stages; Poetry 2.4.1.
- **nginx:** `/health` and `/metrics` answer 404 publicly (prod + dev). The container health check and Prometheus reach the app on the docker network.
- The DSN shown for each app is built from `EXTERNAL_URL`; when it is unset it now uses the request's own base URL instead of a hard-coded `analytics.luxardolabs.com` (a self-hosted instance showed the wrong host). Prod sets `EXTERNAL_URL`, so its DSNs are unchanged.
- **Monitoring consumers:** `/health` now has a typed contract. `database.status` / `redis.status` are `healthy` | `unhealthy` (| `not configured` for Redis), with the error text in a separate `error` field instead of `"unhealthy: <error>"`. `/health` adds `build_commit`.
- **Monitoring consumers:** `/metrics` was always empty (it served a private registry nothing registered into). It now serves the default registry: process, GC and `db_pool_size` / `db_pool_checked_out` / `db_pool_overflow`, read from the engine at each scrape.
- New settings: `LOGIN_RATE_LIMIT` (default `5/minute`) and `TRUSTED_PROXIES` (default loopback + private ranges). `deploy/prod/.env.prod` gains `ALLOWED_HOSTS`, `REGISTRY` and `TAG`, and `DATABASE_URL` moves to `postgresql+asyncpg://`.
- **Release path (LUXANALYTI-53):** the hand-rolled `local-build` / `external-build` / `release` targets are replaced by the emitted image block (`luxarch --emit image-block`, now v10): immutable `:$(VERSION)` and `:sha-<commit>` tags, dirty-tree refusal, candidate scan before every push, no re-push of a released version, GitHub Release from `release_notes/`. One registry; `EXTERNAL_REGISTRY` and `.env.build` are gone. `prod-push` is now `prod-sync`; `prod-deploy` = `prod-pin` (TAG=VERSION in `.env.prod`) + sync + pull + up.
- **Log consumers:** logging moved from structlog to the fleet stdlib JSON module (`app/core/logging_config.py`, LUXANALYTI-52, now asset v5). The log line's `event` field is now `message`; the module's own fields (`timestamp`, `level`, `logger`, `service`, `version`, `environment`) are top-level and every caller field is under `attributes` (a query on `.path` becomes `.attributes.path`). Update any dashboard or alert that keys on `event` or on a context field. The in-process startup migrations no longer relabel every later line as `luxanalytics-migrations`.
- **Tracing:** with `OTEL_EXPORTER_OTLP_ENDPOINT` set, a broken telemetry setup now stops startup instead of silently tracing nothing.

## Fixes

- An app could not be deactivated from its edit panel: an unchecked Active toggle sends no field, and the router wrote `is_active = NULL` (500, NotNullViolation). Unchecked now means inactive. LUXANALYTI-63.
- Creating an app with a taken App ID showed nothing: the 400 carried no swap header, so htmx dropped it. The message now appears in the form's error box.
- `GET /api/v1/stats/overview` was unauthenticated: cross-app event totals, unique-user counts and top event names, readable by anyone. It now requires the dashboard session and returns a typed contract. LUXANALYTI-62.
- `POST /set-app-context` was unauthenticated: anyone could set the dashboard's app-context cookie. It now requires the dashboard session, like every dashboard route. LUXANALYTI-58.
- `POST /login` had no rate limit: unlimited password guessing. Now slowapi, 5/minute per real client, 429 + Retry-After (FLEET-RATE-LIMIT-STANDARD). LUXANALYTI-58.
- Every client shared ONE rate-limit bucket: behind nginx `request.client` is the proxy for everyone. The IP limits now key on the real client via a trusted-proxy-aware X-Forwarded-For read (`app/core/client_ip.py`). LUXANALYTI-58.
- The rate-limit middleware re-ran a request whose handler raised, and swallowed the error; a rate-limited (in-memory fallback) or undecodable-deflate request got a 500 instead of 429/400. LUXANALYTI-59.
- Open redirect after login (`next` accepted absolute and `//host` URLs). LUXANALYTI-1.
- CORS reflected any origin with credentials; TrustedHost accepted any Host in prod; middleware order was inverted; session cookie `Secure` was a DEBUG dial. LUXANALYTI-1.
- **Security:** a compressed request was inflated without bound before any authentication; one ~0.5 MB anonymous request grew the worker by ~0.5 GB (and up to ~10 GB under nginx's cap). Inflation now stops at `MAX_REQUEST_SIZE` and answers 413.
- Request logging at debug level wrote every header, `Authorization`, `Cookie` and the HMAC signature included; it logs named fields only. The engine no longer writes statement parameters (event data) into error logs (`hide_parameters`). LUXANALYTI-11.
- **SDK-facing:** ingest answered every bad request with 500: a malformed event (e.g. no `name`) or a payload that is neither an object, `{"events": [...]}`, nor a list. Now 422 / 400, so an SDK drops bad data instead of retrying it forever; only a real server failure is a 500. LUXANALYTI-61.
- **SDK-facing (LUXANALYTI-80):** a timestamp more than `EVENT_TIMESTAMP_FUTURE_TOLERANCE` (60 s) ahead was a 422, and the SDK drops a 4xx batch, so a device with a fast clock lost every event. It is now clamped to the server's receive time, and so is one before 2000-01-01 (a reset clock; year 1 at an offset was a 500). Between the two, past timestamps (events queued offline) are stored as sent.
- **SDK-facing (LUXANALYTI-69):** `Content-Encoding: deflate` is zlib (RFC 1950) per RFC 9110, which SDK >= 1.1.0 sends; raw DEFLATE stays accepted for SDK \<= 1.0.2. A compressed empty body was a ZeroDivisionError 500; the fallback's debug log carried the first payload bytes. Both fixed; the log names only the format and sizes.
- **SDK contract:** the OpenAPI document (`/openapi.json`, DEBUG only) showed no request body for the three ingest routes, so a client contract check passed anything. The body (one event, `{"events": [...]}`, or a list) is now published, with `EventCreate` / `BatchEventRequest` in components.
- A NUL or a lone UTF-16 surrogate (`"\ud800"`) in an event's name, user/session id or metadata was a database 500; it is a 422. An `id` that cannot be a key (not a string, empty, over 64 characters, NUL, a lone surrogate) no longer rejects the batch: the event is stored without deduplication.
- Any custom-validator 422 at ingest (a future timestamp, a blank name) answered 500: the error context held an exception object that is not JSON. Now a 422.
- The bare-list ingest form is capped at 1000 events like `{"events": [...]}` (it had no cap, and above ~2000 events hit asyncpg's parameter limit as a 500).
- Ingest under concurrency: two requests carrying the same client ids (or devices) in different orders deadlocked on the new unique index (one of each pair got a 500). Rows and device upserts are now written in one key order.
- A device record lost its context when a later event omitted a key: `is_testflight` was reset to false and the OS version, locale and the rest to empty. Now only the keys an event sends update it.
- DSN auth turned every server error during the app lookup into a 401, so a database outage looked like bad credentials to the SDK. Only a malformed header is a 401 now.
- Every HTML page returned 500 after the Starlette 1.x bump (`0cb252e`, never deployed): `TemplateResponse` moved to the `(request, name, context)` form across the wrapper and all 37 call sites. LUXANALYTI-9.
- The "All" time range: the overview and journey pages divided by `hours=0` (500); with "All apps" every query built an empty `and_()`; the events list and the journey's raw-SQL panels read "the last 0 hours" and showed nothing. All-time now means all time everywhere.
- User profile: errors and screens came from the user's newest 50 events only, so older errors vanished ("Errors (0)"); both are now queries over the whole history, and the headings read "N of total".
- Key deep-dive: "Occurrences", unique values and the distribution were computed from a 200-event sample; they are SQL aggregates now. JSON null / "" count as no value everywhere, so totals and rows agree.
- A `/` or `?` in an SDK-sent user id, session id or property key made the events and explorer pages 500 or broke the link; values are percent-encoded and the panel routes take `{…:path}`.
- The performance page 500ed when no event of an operation had a `success` flag; a malformed event id was a database error, now 404.
- The apps list ran one stats query per app; now one GROUP BY.
- A failed database or Redis ping left the health span green; it is recorded now.
- `/metrics`: `db_pool_overflow` read -20 at idle (SQLAlchemy counts up from -pool_size); it is now 0..n.
- OpenTelemetry setup could silently switch tracing off (`add_span_processor` on the API provider, swallowed).
- Shutdown closes Redis through `close_redis_client()` (redis-py 8's `aclose`).
- Release image tag was derived from the checkout directory (`luxardolabs.luxanalytics`). LUXANALYTI-53.
