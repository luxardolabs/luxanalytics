# 2026.10.2 — 2026-10-12

A security release for the dashboard: the four FLEET-AUTH-SESSION-STANDARD rules luxarch 0.289 added (trusted hosts, login CSRF, safe redirects, server-side logout), plus the session-detail count fix. No migrations.

## Notes

**Pre-deploy (prod `.env.prod`, shipped by `prod-sync`):** `ALLOWED_HOSTS` is now **required**, and the app refuses to start without it. Prod is `analytics.luxardolabs.com,luxanalytics_app`; `localhost` and `127.0.0.1` are gone, because the in-container `/health` probe passes without an entry. A self-hoster must set it before upgrading.

**Behaviour change: Redis now gates the dashboard.** The logout stamp lives in Redis, so an unreachable Redis refuses every dashboard session (fail closed). The login page says the session store is down. Ingest does not depend on it.

**Behaviour change: logout is `POST /logout`.** A bookmarked `GET /logout` answers 405.

**Deploy:** `make prod-release` (release, `release-public`, then `prod-deploy`). No migration.

**Rollback:** first put `localhost,127.0.0.1` back on prod's `ALLOWED_HOSTS` in `deploy/prod/.env.prod`. 2026.10.1 has no in-container probe exemption, so without them its own `/health` check (Host `localhost`) gets a 400 and the container reads unhealthy. Then run `make prod-deploy PROD_TAG=2026.10.1`.

## Features

- **Server-side logout** (§2.1): `POST /logout` stamps Redis `dashboard:sessions_valid_after`. `get_current_user` refuses a session whose `login_time` is at or before the stamp. The dashboard has one account, so a logout signs out every session, and a copied cookie stops working. Only a caller with an in-date signed cookie stamps; an anonymous POST revokes nothing.
- **Login CSRF guard** (§5): the emitted `SameOriginMiddleware` (`app/core/same_origin.py`) refuses an unsafe-method request with `Sec-Fetch-Site: cross-site`, or with an `Origin` the app does not serve. The cookie-less SDK ingest paths `/api/v1/events/` and `/api/v1/events/public` are in `cross_site_paths`.
- **Required trusted hosts:** the emitted `AllowedHostsMiddleware` (`app/core/trusted_host.py`, v2) runs over a required `ALLOWED_HOSTS: AllowedHosts`. An unset, empty or `*` value, or a host with a port, refuses to start. The `EXTERNAL_URL`/localhost fallback (`Settings.allowed_hosts_list`) is removed.
- **One safe-redirect helper** (§6): login's `next` and the app switcher's `HX-Redirect` (built from `HX-Current-URL`) go through the emitted `safe_redirect_target` (`app/core/safe_redirect.py`). This replaces the hand-written helper in `app/core/auth.py`, and also refuses percent-encoded tricks (`/%2F%2Fx`).

## Refactors

- `app/core/auth.py`: `_authenticated_user` holds the cookie checks and the stamp check together. `get_current_user` wraps it and fails closed on `SessionStoreError`. `revoke_sessions` replaces `destroy_session`.

## Fixes

- **Session detail:** the count, end time and duration came from the 200-event display list (`len(events)`). A long session read as 200 events ending at its 200th. They now come from `event_crud.get_session_span` (COUNT/MIN/MAX over the whole session). The panel says when it lists only the first `SESSION_EVENTS_SHOWN` events. `tests/test_session_detail.py` failed first (`assert 200 == 205`).
- **Bounced-request query:** `require_auth`'s `next` is URL-encoded, so a bounced request keeps its whole query (`&app_id=` was cut off at the login page).
- **Failed-login redirect:** it now URL-encodes `next`.
- **Adversarial pass on the auth change:** 6 confirmed, all fixed, with regressions in `tests/test_auth_session.py`:
  - a WebView `Origin` on ingest got a 403;
  - a logout during a Redis outage answered "logged out" and revoked nothing;
  - login with Redis down looped silently;
  - a malformed stamp 500'd every signed-in request;
  - the Prometheus Host (`luxanalytics_app`) got a 400 (it predates this release);
  - an `HX-Redirect` built from `HX-Current-URL` could go off-site (it predates this release).

## Known issues

- LUXANALYTI-89 (`fleet-escalation`, open): the same-origin asset's `cross_site_paths` is exact-match only. So the DSN route `POST /api/v1/events/{project_id}` cannot be exempted, and a WebView client that sends an `Origin` to it gets a 403. Native iOS clients send no `Origin` and are unaffected. This is not a guard red: `make check` is green.
