# 2026.10.1 — 2026-10-10

A configuration and observability release: the unread `DATABASE_URL_SYNC` setting is gone, database queries record trace spans again, and tracing is configured through Settings like every other value. No migrations.

## Issues Closed

- LUXANALYTI-85 — `DATABASE_URL_SYNC` was required and read by nothing — removed (owner ruling); an environment or `.env` file that still sets it is ignored.
- LUXANALYTI-86 — No database spans on SQLAlchemy 2.1 — the instrumentor declares `sqlalchemy < 2.1` and instrumented nothing; it now takes the measured bypass from `luxarch --playbook otel-instrumentors`.
- LUXANALYTI-87 — Tracing read `OTEL_*` from `os.environ` with its own default service name — it reads Settings, and the one default name is `luxanalytics`.

## Features

- Database spans: `instrument_database()` (`app/core/telemetry.py`) instruments the async engine's sync core with `skip_dep_check=True`, the sanctioned bypass for instrumentor 0.66b1 on SQLAlchemy 2.1 (`repo.otel_instrumentors_effective`). `tests/test_database_spans.py` measures it with an in-memory exporter: 0 spans before, the query span after.

## Refactors

- `setup_telemetry` reads `settings.OTEL_EXPORTER_OTLP_ENDPOINT` and `settings.OTEL_SERVICE_NAME` (`tests/test_telemetry_settings.py`). A `.env` file now reaches both, and a self-hoster who sets only the endpoint gets `luxanalytics` traces instead of `ll_analytics`.
- `Settings` loads with `extra="ignore"`, so a `.env` written for an older release loads, as the environment already did (it was an `extra_forbidden` failure at import).

## Schema / Migrations

None. Head stays `010_devices_per_app`.
