# 2026.11.0 — 2026-11-18

Hardening release. It fixes the 25 findings of the 2026-10-27 whole-platform adversarial audit and every later finding from its follow-up rounds. Logout now revokes sessions on the server through Postgres. Ingest is rate-limited per device, per address and per app. HMAC replay protection is real. Startup is strict about settings. Guards move from luxarch 0.289.3 to 0.372.0.

## Features

- **Server-side logout** (LUXANALYTI-99): each session cookie carries the generation of the single `dashboard_session_state` row, and `POST /logout` advances it, which signs every session out. An unreadable database or a missing row refuses sessions (fail closed). Startup rewrites a missing row at a random generation. Redis is no longer involved in sessions.
- **Ingest rate limits** (97, 128, 132, 148): budgets per device, per address (IPv6 by /64, with the IPv4 client an IPv6 address carries) and per app, spent all or nothing, on HMAC and DSN alike. `/static` has its own budget (`STATIC_RATE_LIMIT_REQUESTS`). A failed batch is refunded on a connection failure. A Redis reply timeout is decided by the in-memory window.
- **HMAC replay protection** (103, 154): a signed request is processed once inside its timestamp window. The check runs only after the signature verifies. Marks are written after the commit by one drainer, pipelined, on their own small pools, with at most 8 commands in flight.
- **Inactive is a kill switch for HMAC** (122): HMAC ingest answers 403 for an app marked Inactive.
- **Soft-delete for apps** (104, 153): a deleted app keeps its app_id taken and is hidden from the dropdown.
- **Panels scoped to the app** (111, 112, 113): event search, journey exit screens, and the user and session panels are scoped to the selected app. Panel links carry the row's app.
- **Ingest metadata cut** (169): `screen`, `operation` and `button` values over 2000 bytes are cut on a UTF-8 boundary, and the event is stored.

## Refactors

- Tracing is the emitted telemetry module (telemetry v5; LUXANALYTI-91), and services open spans through its helpers. The hand-written `app/core/tracing.py` is deleted (150).
- Request owner `Depends(get_db, scope="function")` commits before the response. Route URLs come from route names. Bucket SQL is typed (LUXANALYTI-92).
- The tests run on the emitted test-db-bound block: each test runs in one rolled-back transaction.
- The exception-handler, same-origin, trusted-host, safe-redirect and logging assets are re-emitted and wired through `install_error_handlers(app)`.
- Removed: `SECRET_KEY` (136), `get_app_id_from_headers` (124), and the dashboard's unused URL helpers and search types (155).

## Schema / Migrations

- `011_dashboard_session_state`: **additive**. It creates the single-row `dashboard_session_state` table and seeds it at a random generation.
- `012_drop_chain_only_defaults`: **catalog-only**, dropping five server defaults that the models do not declare (`apps.app_metadata`, `apps.created_at`, `apps.updated_at`, `devices.platform`, `events.platform`).
  - No table is rewritten.
  - Each ALTER takes an exclusive lock bounded by `lock_timeout = 5s`. Past that the migration fails, changes nothing, and can be re-run. Avoid the daily `pg_dump` window.
  - Downgrade restores the defaults.
- Migrations do not run at container start, so `make prod-migrate` is a runbook step.

## Infra / Ops

- **Stricter startup.**
  - Production refuses to start without:
    - `DASHBOARD_SESSION_SECRET` (117);
    - a non-loopback `TRUSTED_PROXIES` (158);
    - `ALLOWED_HOSTS`.
  - Startup also refuses:
    - a `DATABASE_URL` with an `@` past the authority (142);
    - a blank `HMAC_KEYS` secret (144);
    - a `REDIS_URL` with an unknown query option or one redis-py cannot parse (146);
    - an OTLP endpoint with credentials (145);
    - malformed OTLP headers (157);
    - a request-limit window under 1 s (130).
- `TRUSTED_PROXIES` names exact proxy addresses. The client address is read from every `X-Forwarded-For` line (158).
- Redis clients have a 2 s reply timeout by default. slowapi's synchronous calls are bounded at 0.2 s, and its Redis bound at 1 s. `/health` reports Redis unhealthy when the client failed (151).
- Logs:
  - they carry the route template, never a URL, a typed username, a key or a signature (101, 102, 141, 161);
  - a Redis outage logs its traceback at most once a minute (139).
- Restore is atomic and signs every session out. Dumps leave the session generation out, and `make prod-restore` exists (133, 134).
- The `backup` compose profile takes a daily `pg_dump` with 14 days kept.
- The dev stack runs on the dev host behind the dev edge (160).
- The image's app and alembic files are an allowlist in `.dockerignore`.
- certifi is 2026.10.23, past GHSA-6q48-6c7w-9gw2. This release's image clears the 11 fixable HIGH/CRITICAL findings on 2026.10.2.
- `SECRET_KEY` and `DATABASE_URL_SYNC` are no longer read. An env file that still sets them is ignored, not refused.

## Fixes

- Stored XSS in the journey heatmap tooltip (96).
- A fractional `duration_ms` no longer 500s the performance page (98).
- The 500s are now 4xx or form errors:
  - NUL bytes (108, 159);
  - huge `hours` or `page` values (109);
  - non-object properties (110);
  - app forms (118);
  - a non-latin-1 app_id (107);
  - deeply nested JSON and huge integers on ingest (159).
- Login shows fixed messages only, and the logout confirmation shows (115, 116).
- Security headers (CSP, X-Frame-Options) are on outer refusals and the 500 page (119).
- Time pills URL-encode their filters (114). The slash redirect is relative and answers GET/HEAD only (155).
- App ids:
  - New app_ids are lowercase letters, digits, `_` and `-`.
  - Names must keep a visible character and refuse zero-width and bidi-control characters (106, 155, 171).
- Retry-After is no longer a second short (129).

## Known reds

The owner approved shipping with these on 2026-11-18 (`/release`, recorded on LUXANALYTI-92).

- `repo.compose_pg_healthcheck_tcp` — LUXANALYTI-162 — a false red. The rule judges the backup sidecar's `find /backups` freshness healthcheck as a Postgres probe. Its remedy, a `pg_isready -h 127.0.0.1`, would make that service permanently unhealthy, because no server runs in it. The luxarch maintainer confirmed it (LUXARCH-164 class 3), and it still fails on 0.372.0.
- `fw.no_concurrent_session_use` — LUXANALYTI-168 — a false red. The rule reads the `VerifiedSignature` dataclass (two `str` fields) as an AsyncSession at `app/core/security.py`. There is no session to separate, and the only way to clear it is a cosmetic rewrite that hides the attribute access. The maintainer confirmed it (LUXARCH-164 class 3), and it still fails on 0.372.0.
